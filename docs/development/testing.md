# Testing

mqces uses GoogleTest for C++ unit and integration tests, and pytest for
the Python binding tests.

## Running

```bash
cmake -B build
cmake --build build -j
ctest --test-dir build --output-on-failure
```

For the Python suite:

```bash
cmake -B build -DMQCES_ENABLE_PYTHON=ON
cmake --build build -j
PYTHONPATH=build/python python -m pytest python/tests
```

## Fixtures

Integration tests consume a synthetic 19-class burnup-style fixture
located at `tests/data/fixtures_data.{hpp,cpp}`. It's generated by
`tests/data/generate_fixtures.py`, which also produces a pure-NumPy
reference score matrix (`expected_scores.{hpp,cpp}`) used by
`test_paper_table1` to cross-validate the C++ implementation against an
independent one.

To regenerate the fixtures:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r tests/data/requirements.txt
.venv/bin/python tests/data/generate_fixtures.py
```

The generator is deterministic — the resulting headers should be
committed as part of the change that motivated the regeneration.

## Test layout

| Path                              | What it covers                                              |
|-----------------------------------|-------------------------------------------------------------|
| `tests/unit/`                     | Per-primitive correctness (score, ranks, solvers).          |
| `tests/integration/`              | End-to-end classify() on the 19-class fixture.              |
| `tests/property/`                 | Property-based checks (invariances, monotonicities).        |
| `tests/data/`                     | Fixture generator and generated fixture data.               |
| `python/tests/`                   | Python binding parity vs the C++ reference.                 |

## CI

[.github/workflows/ci.yml](https://github.com/lefebvre/mqces/blob/master/.github/workflows/ci.yml)
runs the full ctest suite on Ubuntu 22.04 and macOS 14, under both GCC
and Clang, in Debug and Release. Sanitizers, coverage, and lint run in
parallel workflows.
